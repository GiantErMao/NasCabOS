# 媒体工具「视频转换」裁剪功能开发计划

日期：2026-10-14  
状态：用户已确认，开发已实施；验证结果见 `VIDEO_CONVERSION_TRIM_IMPLEMENTATION.md`。

## 1. 目标与范围

在现有视频转换任务中增加直接粘贴源文件路径、裁剪区间、与源文件一致的输出格式，以及完成后替换源文件的能力。

计划同步修改 Electron 服务端、Flutter 客户端（桌面/Web/移动端共用界面）和鸿蒙客户端，保持任务创建、编辑、展示及执行规则一致。沿用现有单文件和目录批量处理能力；目录任务的时间区间按每个视频独立判断。

不新增独立裁剪工具，不在确认计划前启动开发、构建或部署。

## 3. 任务属性及界面规则

### 来源

- 源路径输入框可编辑，支持直接粘贴视频文件的服务器绝对路径；保留独立的文件/目录选择按钮。
- 路径指向运行转换任务的服务器文件系统。远程客户端的本地路径不自动上传或转换为服务器路径。
- 去除输入首尾空白，支持粘贴时包裹路径的一对引号；不修改路径内部空格或执行路径文本。
- 服务端验证路径存在、类型及读取权限；粘贴入口和选择入口遵循同一视频识别规则。

### 完成后替换源文件

- 新增开关「完成后替换源文件」，默认关闭。
- 开启后：隐藏保存目录，视频格式强制显示「与源文件一致」且不可切换。
- 关闭后：显示保存目录，恢复用户此前填写的保存目录和格式选择；保存目录必填。
- 开启替换不代表立即覆盖；只有单个视频的输出完成且通过校验后才提交替换。
- 目录任务逐个替换符合条件的视频；非视频文件不复制、不覆盖，记录为跳过。
- 任务详情显示替换开关、裁剪区间和最终格式；替换模式的目标显示「源文件位置」。

### 视频格式

- 新建任务默认「与源文件一致」，其内部配置值建议为 `source`。
- 旧任务保留原有格式；没有格式字段的旧任务沿用原先 MP4 的兼容行为。
- “一致”指输出容器/扩展名一致，不承诺编码、码率、大小或画质与原文件相同；现有编码等设置继续生效。
- 目录中混合格式的视频分别解析自身容器，不使用第一个视频的格式套用整个任务。
- 裁剪模式由起始/结束时间不是 `0-0` 判定。裁剪模式隐藏 WebP、GIF；从动图格式切入裁剪时自动改为「与源文件一致」并提示。后端也拒绝裁剪与 WebP/GIF 的组合。
- 非裁剪且非替换模式继续支持原有 WebP/GIF 转换行为。
- 对源格式建立明确的扩展名/探测容器到输出封装器映射，并校验编码兼容性。不能可靠输出的源格式明确报错，不静默改为 MP4，也不替换原文件。

## 4. 裁剪时间规则

新增并排的「起始时间（秒）」和「结束时间（秒）」输入框，均默认 `0`。支持有限的非负整数和小数；空值提交时按 `0`，拒绝负数、非法文本、NaN 和无穷值。

设视频时长为 D、起始时间为 S、结束时间为 E：

| 输入/条件 | 行为 |
| --- | --- |
| `0-0` | 不裁剪，仍执行正常转换 |
| `10-30`，D ≥ 30 | 输出第 10 秒至第 30 秒，目标时长 20 秒 |
| `10-0`，D > 10 | 输出第 10 秒至结束，目标时长 D−10 |
| `0-30`，D ≥ 30 | 输出开始至第 30 秒 |
| S > D 或 E > D | 不执行裁剪；建议跳过该文件并明确记录原因，不生成整段替代结果，不替换源文件 |
| E 非 0 且 E ≤ S | 保存任务时拒绝，提示结束时间必须大于起始时间 |
| S = D 且 E = 0 | 零长度区间，跳过并记录原因，不生成空文件、不替换 |
| 需要裁剪但无法可靠获取 D | 跳过并报告时长探测失败，不盲目裁剪或替换 |

边界采用用户要求的“大于总长度”判断；结束时间等于时长有效。目录任务对每个文件独立校验，合法文件继续处理，跳过原因在任务进度/结果中可查。全部文件均跳过时不能显示为裁剪成功。

**待确认的语义：**本计划将“超过总长度则不执行裁剪”解释为跳过该视频，而不是继续转换完整视频。这样可避免得到非预期整段输出或替换源文件。若希望超界时仍执行整段转换，应在开发前调整本节。

## 5. 配置与服务端校验

复用 `trans_config`，新增：

```json
{
  "out_format": "source",
  "replace_source": false,
  "trim_start_seconds": 0,
  "trim_end_seconds": 0
}
```

保留现有编码、分辨率、码率、帧率和硬件加速字段。配置在服务端统一解析并校验，不能只依赖前端限制。

- 新字段缺失时：不替换、`0-0`，兼容已有任务及旧客户端。
- 替换模式由服务端强制 `out_format=source`；允许 `target_path` 缺省，存储为空字符串以兼容现有非空列，不让 Worker 使用该值解析输出路径。
- 非替换模式继续要求目标目录有效，并保留源/目标路径冲突限制。
- 替换模式走独立的源文件写权限校验，不能简单移除所有路径冲突保护。
- 保存阶段验证参数；启动及每个文件执行前再次验证实际路径、权限、时长和格式，处理文件已变动的情况。
- 预计无需新增数据库列；实施时确认任务查询、搜索和旧客户端展示对空目标路径的兼容性。

## 6. 裁剪与安全替换流程

1. 获取源文件元信息、大小、修改时间和可用时长；解析实际输出容器，检查裁剪区间。
2. 在输出目录生成任务专属临时文件。替换模式在源文件同目录生成临时文件，避免跨文件系统提交问题；临时文件不得被目录扫描再次当作输入。
3. 使用现有 FFmpeg 转码流程，增加起始定位和有效持续时间（E=0 时取 D−S）。采用准确裁剪的转码方式，不默认使用会受关键帧影响的流复制；时间戳从输出起点归零并保持音画同步。
4. 进度以实际裁剪后的时长计算；硬件加速失败回退的软件转码使用完全相同的区间。
5. 输出成功后校验：文件非空、可探测、有有效视频流、容器符合预期、时长与目标区间一致（容差按帧率与容器时间基确定）；替换模式增加完整解码检查，防止仅头部可读却内容损坏的产物覆盖源文件。源视频有音频时也检查预期音轨与时长。
6. 替换前确认任务未停止、源文件未被修改；防止并行任务同时替换同一路径。发现源文件变化或锁冲突则停止该文件提交并报告原因。
7. 替换采用同目录提交并保留可恢复备份：原文件改名为任务专属备份，再将验证后的临时文件改名为原路径。第二步失败则恢复备份；提交成功并核验后清理备份。保留原权限等可保留的文件属性。
8. 设置提交日志/恢复记录，启动时处理替换过程中崩溃留下的备份；恢复失败保留文件及记录并明确报告，不自动删除唯一可恢复副本。
9. 普通停止、转换失败或校验失败只清理本次临时输出，原文件不变。清理逻辑不能扫描并删除其他任务的临时文件/备份。

现有“目标存在即跳过”规则需区分模式：非替换保持原规则；替换模式不能因为源路径已存在就跳过。重复启动裁剪替换任务会再次裁剪当前文件，界面帮助需说明，恢复任务不能重复提交已完成文件。

**待确认的语义：**“确认产出没问题”按服务端自动校验理解，不增加转换后人工预览确认弹窗。完整解码校验会增加替换任务的耗时，但可提高覆盖前的可靠性。

## 7. 开发步骤（计划确认后执行）

1. 提取并实现统一配置校验、时间区间计算及源容器映射；补充服务端用例。
2. 调整 API 保存与 Worker 准备阶段的条件目标目录校验，验证旧任务兼容。
3. 实现裁剪参数、时长进度和单文件/目录执行规则。
4. 实现输出校验、源文件提交、回滚、停止及崩溃恢复；在临时目录测试失败分支。
5. 修改 Flutter 属性弹窗、任务卡片及语言资源。
6. 同步鸿蒙弹窗、配置构建、任务卡片及语言资源。
7. 执行相关自动化测试、静态检查和端到端验证，记录结果与未覆盖的平台限制。

当前工作区已有语言文件和文件菜单的未提交改动，实施时须保留并仅增量修改本任务内容。

## 8. 验收与验证清单

| 场景 | 验收标准 |
| --- | --- |
| 新建/编辑/重开 | 默认值正确，裁剪和替换配置可保存回显，旧任务保留既有输出格式 |
| 粘贴路径 | 支持中文、空格及带引号的绝对路径；不存在、不可读或非视频路径有明确反馈 |
| 界面联动 | 替换时隐藏保存目录、锁定源格式；关闭后恢复；裁剪时禁止 WebP/GIF |
| 常规区间 | `0-0`、`10-30`、`10-0`、`0-30`、小数秒产物时长及内容正确，音画同步 |
| 时间边界 | 超界、结束早于起始、负数、非法值、S=D、E=D、时长不可探测均按规则处理 |
| 源格式 | MP4/MOV/AVI/MKV/WebM/TS 等映射成功样例；不支持的容器/编码组合明确失败且原文件不变 |
| 混合目录 | 每个文件独立保留格式并计算区间，跳过项可查，临时文件不会成为新输入 |
| 普通输出 | 保存目录必填、原文件不变、已存在目标按旧规则跳过；动图转换回归通过 |
| 替换成功 | 完整验证后输出落在原路径，临时文件和备份按提交状态清理 |
| 替换失败 | 转码失败、损坏输出、无音轨异常、磁盘满、权限不足、提交失败都不丢失原文件 |
| 并发/停止/恢复 | 同一路径提交受保护；停止不覆盖；源文件变动拒绝提交；崩溃后可恢复且不会二次裁剪已提交文件 |
| 硬件回退 | 硬件与软件回退区间一致，裁剪进度正确 |

自动化重点覆盖配置校验、时间边界、格式解析和替换失败恢复；使用临时目录及生成的短视频做 FFmpeg 集成验证，不使用用户真实源文件验证覆盖。Flutter 执行相关分析与交互验证；鸿蒙有构建环境时执行构建检查，无环境则明确标记待实机验证。

## 9. 确认点

确认本计划即可按上述范围开始开发。需特别确认：

1. 超出视频总长度时跳过该文件，不生成完整视频替代结果。
2. “确认产出没问题”使用服务端自动检查，替换前包含完整解码检查。
3. 目录任务也支持裁剪与替换，并按文件独立判断；Flutter、鸿蒙同步修改。

如需调整上述语义，先更新本计划，再执行开发。
