# 视频转换裁剪功能实施与验证记录

日期：2026-10-14。依据已确认的 `VIDEO_CONVERSION_TRIM_DEVELOPMENT_PLAN.md` 实施。

## 已实现

- Flutter 与鸿蒙：可直接输入/粘贴服务器源路径，保留文件选择按钮；新增起始秒数、结束秒数及替换源文件开关。
- 新任务默认「与源文件一致」；旧任务保留原格式。裁剪时排除 GIF/WebP，并在原选择为动图时切回源格式。
- 替换时隐藏保存目录并强制源格式，关闭开关恢复此前的目录和格式。
- 服务端统一校验配置及条件目标路径；`0-0` 不裁剪，结束 `0` 到末尾，超界和零长度区间跳过并记录原因。目录内的视频分别计算区间、解析格式。
- 裁剪采用转码并准确定位起点；进度基于实际区间。硬件转码失败时，软件回退继续使用同一区间。
- 替换前验证文件、视频流、容器、时长及音轨，并执行完整解码；验证通过后提交到源路径。
- 跨进程源路径锁、修改时间/大小/文件标识检查、同目录备份与回滚，以及持久化事务记录。记录位于服务器数据库目录的 `video-trans-replacements`，启动任务前恢复该源路径/目录下未完成的提交。
- 中断或停止后的任务保留运行标识，继续运行时跳过本轮已提交的文件；重新启动已完成的任务会再次裁剪当前视频。修改任务属性会开启新一轮运行。
- 临时文件、内部备份不进入目录任务输入；临时文件清理限定当前进程，避免删除其他正在运行的任务产物。
- 保留工作区原有文件菜单及语言文件改动。

## 格式边界

“与源文件一致”保留容器/扩展名，编码设置仍生效，不代表无损裁剪。

已实现 MP4/M4V、MOV、AVI、MKV、TS/MTS/M2TS、FLV 的明确封装映射。FLV 与 H.265 不兼容；WebM、3GP 与现有 H.264/H.265 编码选项不兼容，源格式输出会明确拒绝。其他尚未映射的源格式同样明确报错，可选择现有 MP4/MOV/AVI 转换，绝不静默改格式或覆盖源文件。源扩展名与探测容器不匹配时也拒绝。

替换不支持符号链接源文件。无法读取的锁/恢复记录，或恢复时源文件出现外部修改冲突，会停止操作并保留备份；不会猜测性覆盖。Windows 使用同卷重命名及已同步的文件记录；Node 不提供 Windows 目录 fsync，断电恢复仍受文件系统持久化语义约束。

## 验证结果

执行：

```bash
cd electron_server
node --test tests/videoTransApi.test.js tests/videoTransCore.test.js tests/videoTransIntegration.test.js
```

结果：**17 项测试，16 通过，1 跳过，0 失败**。

覆盖 API 条件保存目录和配置兼容、非法时间与区间边界、源容器映射、并发锁、源文件变更、停止任务、提交失败回滚、丢失源路径的启动恢复、已提交恢复去重、真实 FFmpeg 区间/小数秒/裁剪到末尾/不裁剪、起点画面内容比对、音轨保留、混合目录统计与跳过原因、硬件失败的软件回退、MP4/MOV/AVI/MKV/TS 封装和 GIF 转换。

跳过的 1 项为 WebP 实际产出：本机 FFmpeg 9.0.1 没有 `libwebp` 编码器。GIF 测试发现旧 `-vsync` 参数已被当前 FFmpeg 移除，已改用 `-fps_mode passthrough`，GIF 回归通过。WebP 编码流程保留，并调整输出探测格式为 `webp_pipe`，但仍需在带 WebP 编码器的环境中确认。

Flutter 相关模块 Dart 静态分析通过：无错误、无警告，仅 `video_trans_view.dart` 原有两条 `unnecessary_underscores` 信息提示。JavaScript 语法检查与 `git diff --check` 通过。
